# skilltab: usage (written before the types)

## What the UI sees

skilltab has one row per **skill body**. A skill body is one physical folder holding a `SKILL.md`. It is not one row per path. `~/.claude/skills/tdd` (a junction), `~/.agents/skills/tdd` (another junction) and `~/.agents/.../tdd` (the real folder) all collapse into one row. That row has one **mount** per place a harness sees the skill.

The UI sends ids that the backend issued, so the webview can never ask the core to delete an arbitrary path. The one path it sends is the setup folder of Export and Restore, which core parses once into a `SetupDir`. An export writes only `manifest.json` and allowlisted files under `config/` in that folder, and it deletes only allowlisted files there. It refuses a folder where `manifest.json` or anything under `config/` is a link. A restore only reads that folder. It writes links and allowlisted files on this machine, and the copy of a differing file beside it as `<name>.from-backup`.

Every change goes through **plan, then apply**. A plan is a pure preview built from the current snapshot: the exact filesystem steps, what else breaks, and what blocks the change. Apply re-checks the plan's preconditions against the live disk before doing anything.

```ts
import { commands, events } from "./bindings";   // generated by tauri-specta from the Rust view types

// 1. Inventory screen. One call returns every row plus the facet values. Filtering is local and instant.
const inv = await commands.getInventory();
const unused = inv.rows.filter(r =>
  r.mounts.some(m => m.harness === "claude-code") &&
  (r.usage.daysSinceLastUse === null || r.usage.daysSinceLastUse > 30));
// inv.facets.harnesses -> [{ id: "claude-code", label: "Claude Code", count: 212 }, { id: "codex", ... }]
// The UI never hard-codes harness ids. It renders whatever the registry reports.

// 2. Detail view.
const d = await commands.getSkill(row.id);
d.skillMd;            // raw SKILL.md text
d.mounts;             // [{ harness, scope: { kind: "user" }, entry: "C:\\Users\\..\\.claude\\skills\\tdd",
                      //    chain: ["...\\.claude\\skills\\tdd", "...\\.agents\\skills\\tdd"], owner: "jstackSync", state: "active" }]
d.usage.series;       // [{ day: "2026-11-01", harness: "claude-code", kind: "model", count: 3 }, ...]
d.jstack;             // { kind: "copyOf", repoSkill: "unslop", drift: { kind: "diverged" } } | null

// 3. Delete from Claude Code only (remove one mount).
const plan = await commands.planAction({ kind: "remove", target: { kind: "mount", mount: d.mounts[0].id } });
// plan.steps    -> [{ kind: "removeLink", path: "...\\.claude\\skills\\tdd" }]
// plan.effects  -> [{ kind: "harnessLosesSkill", harness: "claude-code" }]
// plan.blockers -> [{ kind: "recreatedBy", by: "jstackSync", hint: "add 'tdd' to jstack/exclude.txt" }]
if (plan.blockers.length === 0) {
  const out = await commands.applyPlan(plan.id);   // "stale" if the disk changed since planning
}

// 4. Delete everywhere. The core works out the order: links first, then the real folder to the Recycle Bin.
await commands.planAction({ kind: "remove", target: { kind: "everywhere", skill: d.id } });

// 5. Plugin skills are managed as a bundle, through the harness's own CLI.
await commands.planAction({ kind: "bundle", bundle: d.bundle!.id, op: "disable" });

// 6. jstack. Install and update delegate to jstack's own scripts. skilltab never re-implements its linking rules.
const j = await commands.getJstack(true);   // true = run `git fetch` first to compute "behind"
await commands.planAction({ kind: "jstack", op: { kind: "pullAndSync" } });
await commands.planAction({ kind: "jstack", op: { kind: "installDeclared", source: "mattpocock/skills", skills: ["tdd"] } });

// 7. Restore a setup on a new machine. The folder is a clone of the setup repo. Planning reads and changes nothing.
const restore = await commands.planAction({ kind: "restoreSetup", folder: "~/setup" });
// restore.steps   -> links and files first, then the exact commands, in order:
//   { kind: "link",  detail: "C:\\Users\\..\\.claude\\skills\\own1 → C:\\Users\\..\\setup\\skills\\own1" }
//   { kind: "write", detail: "C:\\Users\\..\\.claude\\CLAUDE.md" }
//   { kind: "run",   detail: "claude plugin marketplace add acme/alpha" }
//   { kind: "run",   detail: "npx --yes skills add acme/skills -g -a claude-code codex -y --skill s1 s2" }
// restore.notes   -> present: "~/.claude/rules/r.md already matches the backup." (no step)
//                    attention: "~/.claude/CLAUDE.md differs from the backup. The backup copy goes to ...from-backup. Compare and merge by hand."
//                    manual: "Sign in to Claude Code. Run claude and follow the login prompt."
// restore.blockers -> a `claude` or `npx` that is not installed, with where to get it. Nothing runs.
// After a completed restore the next plan has no steps, `ready` is false and every item is a present note.
await commands.applyPlan(restore.id);   // stops at the first failing command. Planning again shows only what is left.

// 8. Refresh: rescans the folders and ingests only the transcript bytes appended since the last run.
events.ingestProgress.listen(p => setProgress(p.payload));   // { filesDone, filesTotal, bytesDone }
const report = await commands.refresh();
```

## Call site: the Tauri command shell (Rust)

```rust
#[tauri::command] #[specta::specta]
async fn plan_action(app: State<'_, Skilltab>, action: ManageAction) -> Result<PlanView, CommandError> {
    Ok(app.plan(action)?)
}

#[tauri::command] #[specta::specta]
async fn apply_plan(app: State<'_, Skilltab>, plan: PlanId) -> Result<ApplyOutcome, CommandError> {
    let out = app.apply(plan)?;   // apply ends with a refresh. The outcome carries the new inventory revision.
    Ok(out)
}
```

## Call site: adding a harness (for example GitHub Copilot)

One new file and one line. Nothing in the UI, the usage index, the planner or the TS types changes.

```rust
// core/harness/copilot.rs
pub(super) struct Copilot;
impl Harness for Copilot {
    fn id(&self) -> HarnessId { HarnessId::COPILOT }
    fn label(&self) -> &'static str { "GitHub Copilot" }
    fn discover(&self, env: &Env, projects: &[ProjectRoot]) -> Discovery {
        let mut d = Discovery::default();
        d.scan_skill_dir(&env.home.join(".copilot/skills"), ScopeFact::User, Ownership::Unmanaged, Naming::Plain, 1);
        for p in projects {
            d.scan_skill_dir(&p.path().join(".github/skills"), ScopeFact::Project(p.clone()), Ownership::Unmanaged, Naming::Plain, 0);
        }
        d
    }
    fn usage_sources(&self, env: &Env) -> Vec<UsageSource> { vec![] }   // no usage until the log format is known
    fn session_parser(&self, _resume: Option<&ParserState>) -> Box<dyn SessionParser> { Box::new(NoUsage) }
}

// core/harness/mod.rs: the id const and the single list
pub const COPILOT: HarnessId = HarnessId("copilot");
static REGISTRY: &[&dyn Harness] = &[&claude::ClaudeCode, &codex::Codex, &copilot::Copilot];
```
